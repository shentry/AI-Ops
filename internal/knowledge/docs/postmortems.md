# 历史复盘

## 2026-09-25 运行版本与镜像标签不一致
现象：镜像标签是旧版本，容器内实际运行的却是更新的二进制。原因：后台"系统更新"在容器内替换了可执行文件，绕过了 Compose 发布入口。影响：只比较镜像 ID 会误判运行版本，容器一旦重建就会回到旧二进制，版本回退的判断也会出错。处理：升级到固定 digest 的镜像，生产不再使用后台在线更新发布。教训：确认运行版本要比对容器内二进制版本、镜像标签和 `docker diff`；升级前备份数据库，因为启动时会自动迁移，回退到迁移前的版本必须同时恢复数据库。

## 2026-09-28 容器指标全部缺失
现象：看板上容器 CPU、内存、重启、OOM 全部无数据，`container_*` 只有根 cgroup 的序列。原因：宿主机 Docker 29 使用 containerd 镜像存储，cAdvisor v0.49.1 不支持，日志反复出现 `failed to identify the read-write layer ID`。影响：`Sub2APIContainerRestarting`、`Sub2APIContainerOOM` 实际失效，没有任何告警提示。处理：升级到支持 containerd 镜像存储的 cAdvisor。教训：告警规则依赖的指标要有"有数据"的检查，Docker 大版本升级后核对 exporter 兼容性。

## 2026-09-28 日志链路首次启动误报
现象：Loki 与 Alloy 上线后 `LogPipelineDropping` 立即触发，约 15 分钟后自行恢复。原因：Alloy 首次启动补读了容器数周的历史日志，超过 Loki 保留期的行被 400 拒收，整批计入 Alloy 的丢弃计数；Loki 自身的 rate_limited 拒收里还包含 Alloy 已经重试成功的 429。处理：Alloy 在发送前丢弃超过保留期的行，告警只看 Alloy 最终放弃的条目。教训：丢弃类告警要区分"最终丢失"与"重试成功"，初次上线的补读是预期行为。

## 分组长期没有可调度账号
现象：`Sub2APIGroupNoAvailableAccount` 对某个分组持续触发。原因：该分组配置的账号全部不可调度，属于容量与配置状态，不是突发故障。处理：人工补充账号或停用该分组。教训：这类告警不需要诊断重启或隔离；如果长期保留，应在告警侧处理（补账号或调整规则），避免值班疲劳。
