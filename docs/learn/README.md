## 项目一句话

oncall-agent 是给 **sub2api**（一个大模型 API 网关，Docker Compose 部署，依赖 PostgreSQL 和 Redis）值班用的**自动处置系统**：

1. 接收 Alertmanager 告警；
2. 自动采集证据，让大模型给出根因和一个处置建议；
3. 按预先配置的规则决定「只记录 / 等人批准 / 自动执行」；
4. 执行后用真实业务探针确认是否恢复，再观察一段时间，看会不会复发。

系统自身只依赖 MySQL，不用 Redis、MQ 或向量库。

## 核心思想：模型负责「想」，代码负责「管」，环境负责「判」

整个项目只有这一个主线，后面每个亮点都在落实它。

| 角色 | 由谁承担 | 做什么 | 不能做什么 |
|---|---|---|---|
| **想** | 大模型 | 读证据，调用只读工具补查，写出根因和一个建议动作 | 不能执行任何写操作。它的建议只是一段 JSON 数据 |
| **管** | 确定性代码 | 检查动作前提，按规则授权，冻结批准内容，执行前重查现场，只写一次 | 不把模型自报的置信度、风险当作执行许可 |
| **判** | 真实环境 | 业务探针、容器状态、指标连续多次健康，才算修好 | 模型说「修好了」、命令返回成功，都不算 |

用 Agent 工程的术语说：**Agent = Model + Harness**。Model 是大模型；Harness 是模型外面的一切：给它什么信息、让它用什么工具、它的输出怎么检查、怎么执行、怎么验证、出错了怎么纠正。本项目里 Model 只出现在两处（故障诊断、控制台追问），其余代码都是 Harness。**这个项目的价值主要在 Harness：让一个会出错的模型也能安全地参与生产处置。**

## 一条告警的全链路

以「sub2api 容器进程意外退出，Alertmanager 发出 `Sub2APIDown`」为例：

```text
 Alertmanager
     │ ① 接收与归并 ───────────────────────────────── 亮点一
     ▼
 raw_event ─▶ incident（归并、升级为 firing）─▶ agent_run（排队诊断）
     │ ② 取证  ③ 推理 ──────────────────────────────── 亮点二
     ▼
 11 项证据 ─▶ 大模型：根因 + 建议「重启 sub2api 容器」
     │ ④ 把关  ⑤ 批准 ──────────────────────────────── 亮点三
     ▼
 Guard 查前提 ─▶ Policy 按规则授权、冻结快照 ─▶ 人工批准（或 auto 规则直接批准）
     │ ⑥ 执行 ──────────────────────────────────────── 亮点四
     ▼
 唯一执行器：重查现场 → 只写一次 → 出错先对账
     │ ⑦ 验证  ⑧ 沉淀 ──────────────────────────────── 亮点五
     ▼
 连续 3 次健康 → 观察 30 分钟无复发 → 写入故障记忆
 失败 → 补偿 / 重新诊断 / 阻断规则 / 通知人

 贯穿全程：MySQL 持久队列、同事务提交、审计与回放 ──── 亮点六
 人在哪里介入：飞书卡片、Web 控制室、对话追问 ────── 亮点七
```

## 技术栈

| 层 | 选型 |
|---|---|
| 语言 | Go 1.24（非测试代码约 2.2 万行） |
| HTTP | GoFrame（`g.Server`） |
| 存储 | MySQL 8 + GORM：同时承担业务存储、持久队列和审计 |
| Agent 框架 | CloudWeGo Eino 的 `react.Agent`（ReAct 循环） |
| 大模型 | OpenAI 兼容接口（评测用过 DeepSeek V4 Flash），支持运行时切换模型 |
| 观测数据源 | Prometheus、Docker Engine API、sub2api 管理接口、PostgreSQL、Redis |
| 通知与协同 | 飞书开放平台 SDK（卡片、回调、消息），或普通 webhook |
| 控制台 | React 19 + Vite + TypeScript，构建后通过 `go:embed` 打进 Go 二进制；Playwright 做端到端测试 |

## 项目边界（它不是什么）

- **不是通用自治运维平台**：只服务一个目标系统，只有三个写动作（重启容器、回退发布、隔离上游账号），外加一个补偿动作。
- **不是分布式系统**：执行器是单实例，由 MySQL 命名锁保证。
- **效果还没有端到端验证**：诊断效果只在 12 个人工构造的案例上评测过（到 Guard 为止）。执行后能否真的修好，还没有可重复的端到端评测。
