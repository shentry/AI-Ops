# 输出契约与诊断流水线

> 所属：[亮点二 · 证据驱动的 ReAct 诊断](README.md)

## 一句话

模型的最终输出必须是固定格式的 JSON。动作名只能从已启用的动作里选，参数只能是动作声明过的参数。提示词里的动作清单和解析器的白名单**来自同一份定义**。解析失败就带着原文重试一次。诊断流水线有 6 个阶段，每个阶段都留下审计记录。

## 先弄懂：什么是输出契约

模型输出的是自由文本，下游代码却要精确读取「建议哪个动作、对象是谁」。**输出契约**就是约定一个严格的格式，并在代码里校验。不合格的输出不会进入下游。

## 契约长什么样

```json
{
  "rca": "根因分析，必须引用至少一项证据（用证据段落标题引用）",
  "confidence": "high | medium | low",
  "evidence_refs": ["引用到的证据段落标题"],
  "plan": {
    "action": "none | deployment_rollback | docker_restart | upstream_quarantine",
    "target": {"kind": "container | service | upstream_account | none", "name": "真实存在的目标名，不确定就用 none"},
    "params": {},
    "evidence_refs": ["支持这个动作的证据段落标题"],
    "reason": "该动作能解决根因的理由",
    "confidence": "high | medium | low",
    "risk": "low | medium | high",
    "expected": "执行后预期看到的恢复信号"
  }
}
```

对应的 Go 结构：

```go
// 摘自 internal/llm/reasoner.go
// Plan 只是模型的建议；action 为 none 表示不做任何动作。
// Params 只放动作声明的、模型建议的参数；可信的值由动作自己从配置里补上
type Plan struct {
	Action       string          `json:"action"`
	Target       PlanTarget      `json:"target"` // {kind, name}
	Params       json.RawMessage `json:"params,omitempty"`
	EvidenceRefs []string        `json:"evidence_refs,omitempty"`
	Reason       string          `json:"reason"`
	Confidence   string          `json:"confidence"`
	Risk         string          `json:"risk"`
	Expected     string          `json:"expected"`
}
```

**注意 `confidence` 和 `risk`：** 它们只是模型的自我评估，写进报告给人参考，**从来不作为执行许可**（见亮点三）。

## 动作清单和白名单同源

```go
// 摘自 internal/llm/reasoner.go（有删减）
// NewReasoner 必须在所有工具和动作注册完之后调用
func NewReasoner(factory *Factory, registry *tools.Registry, budget config.DiagnoseBudget) *Reasoner {
	plannable := registry.PlannableActions() // 已启用、且不是补偿动作的动作定义
	actions := make(map[string]tools.ActionDefinition, len(plannable))
	for _, def := range plannable {
		actions[def.Name] = def // ← 解析器用的白名单
	}
	prompt := buildSystemPrompt(plannable)   // ← 提示词里的动作清单
	sum := sha256.Sum256([]byte(prompt))     // 提示词的摘要，存进回放记录，标识提示词版本
	return &Reasoner{prompt: prompt, promptSHA256: hex.EncodeToString(sum[:]), actions: actions /* … */}
}
```

提示词里的动作清单是动态生成的，每个动作写明名称、目标类型、描述、参数：

```text
可建议的动作（系统按已启用的动作定义生成；params 只能包含动作声明的参数）：
- deployment_rollback（target.kind=service）：Return the service to the immediately preceding verified release…… 参数：release_id（必填）：……
- docker_restart（target.kind=container）：Restart the service container once. Only for a process that exited or hangs…… 参数：无
- upstream_quarantine（target.kind=upstream_account）：Stop scheduling one upstream account…… 参数：……
```

**为什么强调同源？** 如果提示词里写死一份动作名单，解析器里再写一份，迟早会不一致：提示词说能用某个动作，解析器却拒绝；或者反过来。比如部署时没配置发布入口，回退动作就不会注册，提示词和白名单里就同时没有它。

## 解析与校验

```go
// 摘自 internal/llm/reasoner.go 的 parseContract（有删减）
func parseContract(raw string, actions map[string]tools.ActionDefinition) (*diagnoseContract, error) {
	cleaned := stripJSONFence(raw) // 模型常常多包一层 ```json ``` 围栏，剥掉。这是宽容，不是契约
	var contract diagnoseContract
	if err := json.Unmarshal([]byte(cleaned), &contract); err != nil {
		return nil, &contractError{raw: raw, err: err}
	}
	if strings.TrimSpace(contract.RCA) == "" {
		return nil, &contractError{raw: raw, err: errors.New("plan JSON missing rca")}
	}
	switch contract.Confidence {
	case "high", "medium", "low":
	default:
		return nil, &contractError{raw: raw, err: fmt.Errorf("invalid confidence %q", contract.Confidence)}
	}
	if contract.Plan.Action == "none" {
		return &contract, nil
	}
	def, ok := actions[contract.Plan.Action]
	if !ok { // 编造的动作名
		return nil, &contractError{raw: raw, err: fmt.Errorf("plan.action %q is not none or an enabled action", contract.Plan.Action)}
	}
	// params 里的每个参数都必须是该动作声明过的
	for name := range params {
		if !declared[name] {
			return nil, &contractError{raw: raw, err: fmt.Errorf("plan.params.%s is not a parameter of %s", name, def.Name)}
		}
	}
	return &contract, nil
}
```

**解析失败，带着原文重试一次：**

## 诊断流水线：6 个阶段

`Pipeline.Run` 把一次诊断串成 6 个阶段，每个阶段都是 `agent_run_step` 表里的一条记录（seq 是序号）：

| seq | 阶段 | 做什么 | 失败时 |
|---|---|---|---|
| 1 | 记忆查找 | 同类故障有没有验证过的方案（亮点五）。命中就跳过第 3 步 | 查不到就当未命中 |
| 2 | 证据采集 | 11 个采集器 → 渲染 → 存快照 | 快照存不下 → 诊断失败 |
| 3 | 推理 | ReAct → 契约校验 | 解析 / 超时 / 超限 → 诊断失败 |
| 30–89 | 工具调用 | 每次工具调用一条记录（最多 60 条） | — |
| 4 | Guard | 用结构化事实检查动作前提（亮点三） | 不满足就把动作改成 none |
| 5 | Policy | 按处置规则授权、冻结快照（亮点三） | 拒绝或降级为人工 |
| — | 提交 | 诊断结论、审批单、事件**同一事务**提交 | 提交失败 → 不发通知 |
| 6 | 通知 | 发诊断报告（飞书卡片等） | 发送失败**不改写**已提交的诊断结果 |

```go
// 摘自 internal/diagnose/pipeline.go 的 Run（骨架，大量删减）
func (p *Pipeline) Run(ctx context.Context, run store.AgentRun) error {
	target, err := p.builder.LoadTarget(ctx, run.IncidentID)

	// 1 记忆查找（重诊不查记忆）
	if run.RetryOf == nil { /* 命中：rca、plan 取自记忆，run.Mode 改为 memory_hit */ }

	// 2 证据采集（记忆命中也要采：Guard 只信本次的事实）
	collected, rendered := /* BuildForIncident + Render */
	p.db.SaveDiagnosisSnapshot(ctx, snapshot)

	// 3 推理（记忆命中时跳过）
	if run.Mode != "memory_hit" {
		result, err := p.runReasonStep(ctx, run, evidence, &snapshot)
		rca, confidence, plan = result.RCA, result.Confidence, result.Plan
	}

	// 4 Guard：确定性规则，之后没有任何环节能改回它的结论
	guardResult := Guard(rca, plan, collected)
	if guardResult.Overridden {
		plan = guardResult.Plan // 被改成 none
	}

	// 5 Policy：规则授权。输入是当前的告警事实和 Guard 确认过的身份，不是模型给的
	decision := p.policy.Decide(ctx, plan, approval.PolicyInput{ /* … */ })
	var draft *store.Approval
	if decision.Kind == approval.DecisionApproval || decision.Kind == approval.DecisionAuto {
		prepared, _ := p.approvals.Prepare(run.IncidentID, run.ID, decision, reason)
		draft = &prepared
	}

	// 诊断结论和执行许可在同一事务里发布。提交失败时，不发通知，也不做第二次完成
	if err := p.db.CompleteRun(ctx, store.RunCompletion{RunID: run.ID, RCA: rca, PlanJSON: planBytes,
		Status: "succeeded", Approval: draft /* … */}); err != nil {
		return err
	}

	// 6 通知在提交之后：发送失败不能改写诊断结果
	notifyErr := p.reporter.NotifyDiagnosis(ctx, report)
	// ……记录通知步骤……
	return nil
}
```

任何阶段失败都走 `p.fail`：把 run 标记为 failed，失败事件和终态在同一事务提交。`run.failed` 属于「需要人关注」的事件，会自动进入通知队列（亮点六）。

## 常见追问

- **既然动作名已经有白名单，为什么还要 Guard 和 Policy？** 白名单只保证「动作名合法、参数合法」，不保证「这个动作在当前情况下是对的」。Guard 检查事实前提，Policy 检查规则授权，是不同层次的问题。
- **模型给 `confidence: high`，会更容易执行吗？** 不会。执行只看规则。置信度只影响两件事：写进报告给人看，以及作为写入故障记忆的条件之一（亮点五）。
- **换模型会不会影响契约？** 不会。契约由代码校验，和具体模型无关。系统支持运行时切换模型（管理员接口），切换后同样的提示词、同样的校验。
